# Graphr 0.6.0 Immutable Worktree Snapshots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Graphr's implicit startup-checkout state with explicit allowed roots, exact Git target capture, immutable snapshot-scoped queries, and asynchronous indexing, then pass all ten generic 0.6.0 acceptance tests.

**Architecture:** Keep the existing Git capture, parser, graph builder, SQLite store, artifact analyzers, and bounded four-section renderer. Add one root/snapshot module for canonical identity, immutable cache publication, and provenance, plus one small job registry for per-workspace asynchronous work. Every graph query opens a published snapshot; no query discovers a repository, resolves a ref, reads an index, or reads a worktree.

**Tech Stack:** Rust 2024, Rust standard library, Git CLI, existing BLAKE3, serde, rmcp stdio, SQLite/rusqlite, Tree-sitter Rust/Python, Cargo.

## Global Constraints

- Build one Rust binary for Codex and Claude over MCP stdio.
- Rust and Python remain the only indexed source languages.
- Markdown, TSV, and bounded generic text remain artifact-review formats, not indexed source languages.
- Add no crate, migration, compatibility protocol, fallback checkout, HTTP surface, UI, editor integration, embeddings, plugin system, or automatic cache garbage collection.
- Remove `graphr serve PATH`, startup indexing, mutable `.git/graphr/index.db`, `changes(base=...)`, default snapshots, and `--rebuild`; do not retain aliases for them.
- Keep output deterministic, compact, line-safe, independently paged, and bounded by the existing response budgets.
- Preserve no-follow reads, canonical-path checks, regular-file and size checks, two-sample capture validation, Git deadlines, cancellation, SQLite rollback, and explicit incomplete-coverage semantics.
- Treat Git refs as labels only. Resolve base and head once and use exact OIDs thereafter.
- Never write HEAD, refs, the worktree-specific index, Git objects, attributes, configuration, or worktree files. Cache writes are limited to the validated `graphr/v6` directory under the common Git directory.
- Use the standard library and existing dependencies only. Use `rmcp::serde_json` for manifest and structured-result JSON rather than adding `serde_json` directly.
- Use test-driven development for every production behavior.
- Do not use any customer, incident, or ticket-specific name in fixtures, docs, code, or commit messages.
- Run `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `cargo build --locked --release` before the completion claim.
